# Boundary rules

These are the exact rules, bounds and formats behind BOUNDARY-001 in [CONTRACT.md](../../CONTRACT.md). The contract holds the requirement and its acceptance; this page holds the mechanism they rely on, as recorded when the contract was rewritten to the RER contract standard on 28 October 2026.

A region counts as US when its name starts with "us" followed by a separator or digit (us-east-1, us-central1, US), names the United States, or is an Azure US region (eastus, westus2, centralus); any other named region is non-US. This clause is done when every capability that exists today conforms; each future clause that adds a program, agreement, specialist handoff or customer-facing claim (PROGRAM-003, PROGRAM-004, VENDOR-001, VENDOR-002, ANSWER-001, TRUST-001, AUDIT-001) inherits the same prerequisites, no-certification and USD-disclosure obligations before it ships.

Status note: None for current doors. Future program, agreement, specialist-handoff and customer-facing clauses (PROGRAM-003, PROGRAM-004, VENDOR-001, VENDOR-002, ANSWER-001, TRUST-001, AUDIT-001) inherit the obligation.
