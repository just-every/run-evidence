# Tracker sync rules

These are the exact rules, bounds and formats behind WORK-001, WORK-002 and WORK-003 in [CONTRACT.md](../../CONTRACT.md). The contract holds the requirement and its acceptance; this page holds the mechanism they rely on, as recorded when the contract was rewritten to the RER contract standard on 28 October 2026.

**Current semantics (23 October 2026):** All thirteen destination paths have a WORK-001-named public-door matrix for mapped creation, assignee/status read-back, unchanged-read idempotence, due-date conflicts, deletion, grant loss/recovery and closure-triggered source re-tests. Priority and labels use native fields where available: label IDs for Vector/Linear, Asana workspace tags and a project Priority enum, Shortcut's Priority enum, monday tags and priority columns, and YouTrack tags/custom fields. Missing or ambiguous mappings refuse creation visibly. Basecamp to-dos have no native priority/label fields; their text representation remains explicit. Title, description, source links, priority and labels are set at creation. The signed-in human owner can also write explicitly mapped native tracker assignees and statuses, separately from Evidence's accountable owner and compliance state. The field editor reads native identities and a new source read precedes every write; if a selected field changed since the displayed snapshot, no field is written and both tracker and requested values, expected snapshot, actor reason and UTC conflict time remain in Sync history. Unknown native identities refuse writes. Read-back must confirm the requested identities; lost or unconfirmed outcomes stay uncertain and are never reported as success. This check does not claim an atomic lock against provider edits after the final read. Tokens, agents and unsigned-in sessions cannot use this owner-session door. Azure dates use the owner-mapped writable DateTime field at UTC midnight; reads compare UTC calendar days. GitHub Issues has no native due-date field: its editable `Evidence due date:` body line is synchronized, with the same explicit conflict/resolution rule as native deadlines, preserving other issue text. Removing that line creates a conflict; malformed dates stay unavailable. Authenticated native callbacks now prompt read-back for Azure Boards (Basic service-hook credentials), monday (integration-app signed JWT), Freshservice (authenticated Workflow Automator POST) and YouTrack (`X-YouTrack-Token`). Polling batches count distinct destination/remote-ticket pairs (at most fifty per tick), including every linked item of a whole-test ticket together so one closure queues a complete re-test. Their payloads never establish tracker truth; repeats are admitted once and project/destination boundaries remain enforced. Shortcut signed batches and the existing callback paths remain supported. Basecamp now has owner-registered secret-address callbacks (unsigned provider events), exact event-ID deduplication, account/project checks, hourly deactivation checks and a polling backstop, asserted through public doors against its official-schema network fake. Vector comment reads follow its published API-003 Comment schema and cursor protocol with the additional `comments:read` scope. Every destination retains the first observed comment text (up to 2,000 UTF-16 code units, visibly marked when truncated), source display author, stable comment ID, original source time normalized to UTC separately from receipt time, and a source link (the provider's safe same-origin permalink where exposed, otherwise the linked ticket). Earlier snapshots are not rewritten by later source edits. Source metadata survives restart and custody restore beside the retained history. Omitted source times stay unavailable. A denied, malformed, foreign-issue, unsafe-link, repeated-cursor or incomplete Vector page fails the read without admitting partial comments; all page filters stay bound to the linked issue. SQL deduplication prevents competing reads from duplicating either the comment or its attribution. Source HTML is inert text; only the owner's existing private doors expose the history, never a source-read API token. Vector reads at most 201 pages per sync; exceeding the bound fails visibly rather than claiming completeness. AUTH-001 inherits the same source-comment privacy on future delegated doors. Evidence-origin mapped tracker assignee/status writes and their conflict/authority doors are asserted for all thirteen destinations; editing Evidence's accountable owner/compliance state separately does not satisfy those writes. AUTH-001 carries their scoped people-only authorization before delegated roles ship; PORTABLE-001 carries callback registration custody. Live Gap for each destination: **not yet run against a live account**; no provider verification is claimed.
