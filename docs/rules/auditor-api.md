These are the exact rules, bounds and formats behind AUDIT-001 in [CONTRACT.md](../../CONTRACT.md). The contract holds the requirement and its acceptance; this page holds the mechanism they rely on, as recorded when the contract was rewritten to the RER contract standard on 28 October 2026.

**Current native API semantics (23 October 2026):** The owner explicitly authorizes engagement-scoped native auditor identities through the documented `docs/AUDITOR-API.md` doors. Only the owner submits exact existing receipts, imports request lists, assigns current people and closes accepted work. Auditors append attributable comments and versioned decisions against the latest submission; an upload never counts as acceptance. All receipt intervals must fit wholly within the inclusive UTC period, and observation timestamps must fall inside it. Shared request evidence includes the original source reference, connected provider and account where available, receipt time and digest, and approved exceptions intersecting the period. Program checklists count engagement and request records separately from readiness passes. Open requests join the existing departure handover and escalation workflow. All new records join custody archives; restored grants are revoked. ct approved the dedicated native identity and grant policy on 23 October 2026 at 14:35Z. Auditors are refused at non-audit product doors and at the exact engagement-grant expiry, as asserted by the named native journey. Provider sign-in remains AUTH-001; request-free continuous review and Restricted detail remain AUDIT-003.
